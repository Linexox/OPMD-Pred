## 1. 最先要处理的评价阻碍

1. **当前不能证明患者独立。** processed 只有 139 个唯一 `sample_id`，其定义是 `level + Excel行号`，不是患者 ID。原表有姓名，但没有可见的匿名患者 ID、就诊/复诊 ID 或检查/病理日期。标准化姓名共有 131 种，8 组共16条同名记录，其中7组跨类别。姓名同名不证明是同一患者，异名也不证明是不同患者；131不能作为真实患者数。需要医院确认的匿名患者及就诊标识，跨次就诊仍按患者分组。
2. **已证实同图异标签及跨拆分重复。** 87张图中2组共4条记录的字节 SHA256及解码 RGB完全相同，两组均跨 level1/level2。当前 seed42 随机记录拆分有1组同图跨 train/validation，另有2种标准化姓名跨 train/validation。先由导师/数据负责人核对重复图对应病理标签、时间与绑定来源；不自动改标签。同图去重分组可以防止该种泄漏，但不能替代真实患者分组。
3. **当前15%验证集不支持稳健临床结论。** 默认训练118条（56/31/31）、验证21条（10/5/6）；没有独立测试集。验证准确率每一条改变4.76个百分点，重度召回每一条改变16.67个百分点。训练反复按该验证集选择epoch不能把其准确率作为最终泛化证据。
4. **检查时间及标签定义待补证据。** 三个等级源于三个工作表/文件归属，原表没有本审计可核验的独立病理报告及先后时间。TCT/DNA/甲基化可以是诊断前检测，也可能与诊断或分组流程有关；当前数据不足以判断。需要明确任务预测时点、病理金标准及检测是否在预测时点可用，不把未核实的“诊断意见”视为已排除标签泄漏。

在这些问题得到处理前，可以构建代码和报告探索性结果；不能宣称患者独立75%或临床有效性。

## 3. 原始字段与图片准备

### Excel active sheet 会造成严重复现错误

`scripts/prepare_sysu.py:41` 使用 `workbook.active`。实际moderate.xlsx有：`moderate`36条、`Sheet2`10条、当前active `Sheet3`7条。重跑现有脚本将误取Sheet3，且脚本先删除processed图片。

本次审计显式选取 `mild`66条 / `moderate`36条 / `severe`37条；全部14个训练字段逐行清洗后与当前processed CSV完全一致。当前processed不是“只有7条中度”；问题在于重新准备时依赖active。应显式指定表名、校验期望schema和来源SHA，另输出到新目录核对后再切换，避免直接覆盖当前processed。

### 图片匹配不充分保证患者绑定正确

`prepare_sysu.py:55` 按姓名/目录名前缀双向匹配、字典序选第一个未用目录；level1和level3各有2条记录对应多个候选目录。同名记录保留独立样本，且目录名常带附加后缀；找到前缀不是身份确认。当前87张processed图的字节均能在对应源候选目录找到，证明复制来源一致，不能证明源目录属于正确患者/就诊。

源目录有90张精确stem“病损”图，另有175张带“病损1”等编号的图；processed只保留87张精确stem图。175不是175个新患者，不能直接作为独立样本扩增。若纳入多图，需可靠patient/encounter group、标签归属和同患者聚合；不应在不分组时增加训练/测试条数。

本次仅确认字节和完全相同RGB重复；尚未完成裁剪、旋转、压缩近重复审计。

### DNA、甲基化的语义

- 原表139个DNA结果都是Excel公式 `DI≥2.3细胞数 / 分析上皮细胞数`，有值123条，16个公式错误为缺失。现用输入是一个细胞比例，而不是完整DNA倍体直方图；比例范围0–0.0531504，零值有效、不能当缺失。该输入的训练内缩放可考虑log1p或训练分位数/标准化，但不能从全数据学习归一化。
- 当前甲基化是总数，89条、范围0–10，三类中位数1/2/5。原表十基因0/1面板仅62条全齐（30/13/19）；另外77条基因全缺，而其中部分仍有总数。不能凭总数重建基因身份，不能将`NAN`/None补成阴性0。进一步用基因特异信息需确认总数来源、panel完整性和测量时间后另建可审计预处理。
- `几十年`在processed编码30，README已说明是近似；该近似在后续解释中应标注而非视为精确测量。
- TCT有5种类别。`未见核异质细胞`共90条（53/25/12）；`未见异常`4条全在重度；其余为非典型或可疑异型意见。医学语义及不同用词应由导师确定，不能仅按字符串自动把相近术语合并或赋予有序等级。检测意见与病例选择路径有关的可能性需纳入解释。

## 5. 当前SHAP/交互解释的范围

- `coalitions.py`对模型融合token进行所有模态coalition遮蔽；自然未观测模态保持未观测，是合适的约束。`shapley.py`价值函数为**期望严重度**（两个sigmoid之和，0–2），不是每类概率解释，不是因果效应。
- 基准是全部missing-token模型输出，不是背景样本分布SHAP。之前dropout一般强制至少保留一个观测模态，全缺失coalition可能超出该模型训练支持；需要描述并检查该基准的稳定性。
- 模态Shapley离散枚举公式和对称成对off-diagonal交互公式可用于该missing-token游戏。当前interaction矩阵diagonal始终零，未补SHAP interaction分解中的main effect；图上不能把零对角误读为主效应不存在。必须清楚定义显示“成对交互”还是完整交互分解。
- 用户改动中的`global_interaction_ratio = mean(abs(interaction))/mean(abs(full_expected_severity))`受严重度零点、offset及类别分布影响，不是本审计已核验的标准InterSHAP指标；不要以字段名声明复现论文指标。需文献调研者核对原文定义/代码，并分别报告有符号与绝对交互。
- 自然缺失模态作为dummy player在该游戏中应给零贡献；这表示**当前没有观测该输入**，不是阴性，也不是“此检查无用”。解释应同时显示自然观测mask与模拟遮蔽。
- 当前只有模态级解释，不提供病灶定位；需要局部图像归因及扰动/随机化稳定性验证。热图不能代替病灶标注或作为癌前病变诊断依据。
