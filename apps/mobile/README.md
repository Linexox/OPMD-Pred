# 口腔随访 · Android Demo

白色卡片、浅紫待办、三步录入。患者整理就诊资料，医生演示角色复核并使用冻结研究模型。

## 在这台电脑和手机上使用

1. 在Android手机安装 `D:/.Workspace/医工/口腔随访-20261011-debug.apk`。
2. 电脑双击 `D:/.Workspace/医工/启动手机APP服务.cmd`。保持窗口打开；窗口显示地址与连接口令。
3. 手机与电脑连接同一Wi-Fi，在“我的→连接电脑”填写地址和口令。地址使用电脑的Wi-Fi IPv4，不填localhost。
4. 可建立匿名档案；也可点“载入模拟档案”，查看两种虚构流程。

若已有服务占用8765端口，继续使用原窗口，或关闭原窗口后再启动。手机无法连接时检查电脑网络是否允许本服务；不需要开放互联网端口。演示调试包支持局域网HTTP，正式版本需另行配置加密部署和身份认证。

当前电脑Wi-Fi网卡名为WLAN。如Windows防火墙拦截同Wi-Fi访问，在管理员PowerShell执行同级服务目录的 `allow-lan.ps1`；只允许WLAN同网段访问8765端口。本轮未获得管理员权限，不自动修改防火墙。

## 小陈补照片：三分钟演示

“模拟：补照片”档案首页有右舌侧缘任务。点“去补充资料”→拍照或相册选择→核对→提交。

在“我的→演示医生视图”打开等待复核的补充记录，填写复核人代号、意见，确认发送。回到患者页查看反馈。医生可另外进入研究辅助；运行失败时保留资料并显示原因。

资料任务：待补充→已提交→医生确认。线下复诊只记录患者自报完成。不同就诊、部位独立保存；修改后需要重新复核，旧反馈及研究结果留在历史。

## 保存在哪里

- 手机：输入草稿、未发送医生意见、待上传附件，使用应用私有文件存储。切换页面或重启可恢复。
- 电脑：默认 `%LOCALAPPDATA%/OPMDMobileDemo`，包含SQLite、附件、配对口令及研究运行记录。
- 本版角色切换用于演示；已提交数据依赖电脑服务，断网时可继续整理手机草稿。
- 报告PDF/JPG/PNG，单文件20MB以内；拍照使用系统相机，图片保留上传原始字节。
- 系统在相机或文件选择过程中回收APP时，输入草稿仍保留；尚未返回的拍摄结果可能丢失。可点“新增”恢复草稿并重新拍摄或选择。自动回到拍照步骤尚未稳定复现。
- 检测字段保存后，在记录详情展开并核对来源，再重新提交。空值保持缺失；DNA真实零值与0/0不同。

## 构建与复现

Node 24、Java 21、Android SDK API36；锁定npm依赖。当前SDK位于 `D:/.Workspace/android-sdk-opmd`。

```powershell
./build-android.ps1
```

APK输出：`android/app/build/outputs/apk/debug/app-debug.apk`。源码在 `codex/sysu-proxy-balanced` 分支。服务源码见同级 `mobile_service`；保持同级 `patient_demo` 及项目src可访问。

浏览器检查脚本和Android检查脚本使用当前电脑的Playwright运行时，输出独立证据目录；Android脚本控制调试WebView，系统相机/报告选择使用adb检查。它们属于工程验收，不是医生评审或真人用户试用。

当日交付与限制见主仓库 `docs/daily/2026-10-11/README.md`。Android模拟器拍照仅为虚拟场景；实际手机拍照、医生评审及5位模拟用户试用仍待安排。
