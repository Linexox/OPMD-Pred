# 口腔黏膜自查与随访助手 · Windows桌面Demo

首版覆盖首次自查资料准备和已就诊随访，使用PyQt6、SQLite及本地附件；没有云服务或患者自动诊断。模型概率仅在演示医生视图中出现。医生账号认证、手机安装包及医院接口不属于本版。

## 10月10日更新：患者“下一步”和分步输入

新增首页“下一步”；准备资料分为描述情况、照片与已有资料、核对提交三步，检测字段可展开。切换档案或关闭时可保存草稿、放弃修改或继续编辑；错误显示在相关字段附近。正文16px，主要按钮至少44px。

医生在“复核意见与任务”可选择待补照片、报告、病史或其他，并写具体说明。患者点击任务会建立关联的补充记录，档案与部位锁定；待补充→已提交→医生已确认。重复提交不创建重复任务，修改后重新核对。线下复诊显示患者自报完成，与资料确认分开。旧数据库迁移前自动备份，旧任务保留。

医生“研究辅助”使用资料、缺失、分数及状态卡片，原始运行JSON折叠。默认冻结模型仍是原fold0基线；今天距离损失的研究结果没有替换它。若旧Demo窗口仍开着，请关闭后重新启动新版。

## 三分钟演示流程

1. 可先点击“载入两种模拟案例”查看虚构流程；模拟反馈不代表真实医生意见。也可建立匿名档案，选“首次自查”或“已就诊随访”、日期和部位，填本次记录。
2. 选择照片，可追加多份报告附件。技术提示只检查尺寸、灰度明暗、Laplacian方差，不证明病损可见或无病。原始照片和SHA在私有本地保留，显示副本去除EXIF。
3. 检测字段可以留空。DNA使用异常细胞数、分析总数、DI阈值2.3/2.5；0/有效总数是真实0，0/0是缺失。明确填写取材部位和来源；新附件保存后再次核对并勾选确认。任何检测值、日期、部位、来源或附件SHA改变都会使旧确认失效。
4. 保存并提交复核，切换“演示医生视图”。填写复核人代号、意见；可要求补资料或填写复诊日期和任务。确认后切回患者视图查看反馈、历史及待办。
5. 医生研究视图可运行实时研究推理。输入以已保存版本为准；没有模型、输入错误或运行失败时明确显示失败，全缺输入拒判，不生成替代分数。
6. 患者“反馈与历史”可导出就诊摘要PDF。摘要含人工确认反馈和任务，排除研究模型概率。修改同一记录后当前反馈清空待重新复核，旧反馈在历史快照中保留。

首次自查没有检测报告也可提交。检测未确认时，TCT/DNA/甲基化不进入推理；病史和图片仍按现有mask处理。未知TCT使用训练接口中的unknown ID=1，不映射为正常。症状、日期、部位、身份不进入模型，年龄和性别不收集。

## 模型与结果边界

`models.local.json`配置私有模型路径和CPU/CUDA，样例见`models.example.json`。不提交模型或医院资料。

- 固定seed42常规基线fold0完整分类器；SHA `f00181a650d1927c40cbc026b55b4f57dd4dd9946649cb775a85b60f2852a321`。
- Zenodo-SAM-DINOv2-B/14编码器；SHA `58a3fcc724155c8ecfc7bf0e955b2bf022f0e2aa4bfed06a51a5b99c850a4a65`。
- 518等比例补边、1536维CLS＋patch均值、原报告DNA比例＋DI阈值两个输入、固定中位数0.5决策及分类器内TCT词表。
- 模型不更新参数。类别为正常/轻度、中度、重度，未校准为癌变概率，未验证社区初筛、患者自拍或长期结局；不能把fold0对训练病例的输出算作未知测试结果。

## 工程接口与验收

`Store`以患者UUID和就诊UUID分离记录，独立保存部位、附件、版本、反馈快照及任务。`ResearchEngine.predict(visit,root)`返回predicted/abstain或抛出错误，由GUI保存failed记录；QThread在后台执行，并按启动时的就诊ID和revision归档。SQLite连接仅在主线程使用。

在新电脑安装Python 3.11+并安装`requirements.txt`；将本工程`src`和Demo一起保留，配置两份SHA匹配的模型路径。可显式传`--data-dir`、`--model-config`。部署到医院或患者手机需另外实现认证、服务和实际场景验证。
