# 远程服务器访问

按本项目的服务器约定，帮助用户连接公共服务器并在个人目录中完成准备工作。所有远程写入、依赖安装和任务运行都应先确认当前目录位于个人目录 `~/24334067`。

## 登录

使用已配置的免密 SSH 命令：

```bash
ssh zjkj@www.ming56.cn -p 9019
```

用户提供的反斜杠只是转义写法；在 shell 中使用上面的标准命令即可。登录后先确认主机和目录，再开始写入或运行任务：

```bash
hostname
cd ~/24334067
pwd
```

如果 `pwd` 不是 `/home/.../24334067`（或该服务器上对应的 `~/24334067`），先切回个人目录。不要把 `~` 当作项目目录，除非 `pwd` 已确认。

## 初始化脚本

`init.sh` 是个人 Git 身份和 GitHub SSH key 配置的权威入口；S需要初始化 Git 或认证失效时，在个人目录中找到并运行它：

```bash
cd ~/24334067
find . -maxdepth 3 -type f -name 'init.sh' -print
```

确认路径后按脚本要求运行。当前项目的 `init.sh` 必须在当前 shell 中加载，以便配置个人 Git 身份和 SSH key：

```bash
cd ~/24334067
source ./init.sh
```

如果脚本不在当前目录，只在确认路径后使用 `source /实际路径/init.sh`。不要用 `bash ./init.sh` 替代 `source`，否则脚本中的 shell 函数和环境配置不会保留。如果个人目录没有找到，再在 `~` 下仅列出可能的脚本路径；不要为了查找脚本而打印整个脚本内容，因为其中可能包含令牌或其他敏感配置。不要在命令行中手工输入、回显或提交 Git/Hugging Face 凭据；脚本中也不应保存硬编码令牌。

初始化完成后，可做不泄露凭据的检查，例如：

```bash
git config --global --get user.name
git config --get user.email
git config --get core.sshCommand
ssh -T -o BatchMode=yes -o IdentitiesOnly=yes -i ~/24334067/.ssh/lhf-key git@github.com
```

若检查命令输出令牌、私有信息或异常内容，不要复制到聊天、日志或仓库中。

## 公用服务器约束

- 个人项目、代码、数据、缓存、模型和临时文件放在 `~/24334067` 及其子目录；不要写入其他用户目录、系统目录或公共共享目录。
- 不要假设拥有 `sudo` 或管理员权限；没有明确授权时不要修改系统软件、服务、SSH 配置或全局环境。
- 运行破坏性命令前确认路径和目标，尤其是 `rm`、批量移动、清理缓存、覆盖数据和终止进程；不要使用无范围的清理或 `kill`。
- 不要在共享目录留下访问令牌、密钥、cookie、私有数据或包含凭据的日志；提交 Git 前检查 `.gitignore` 和变更内容。
- 安装依赖、创建虚拟环境和下载模型时优先使用个人目录；避免占满公共磁盘、内存或 GPU。大规模任务先检查资源和已有进程，避免影响他人。
- 远程操作前后报告实际主机、当前目录和关键命令结果；遇到权限、配额、网络或认证问题时停止扩大操作范围，并保留错误信息供定位。

## 默认工作顺序

1. SSH 登录。
2. `hostname`、`pwd`，切换并确认 `~/24334067`。
3. 按需运行个人目录中的 `init.sh`。
4. 再执行项目命令；所有输出、生成物和缓存保持在个人目录。
5. 完成后检查 Git 状态和临时文件，避免把凭据或大文件留在不应共享的位置。
